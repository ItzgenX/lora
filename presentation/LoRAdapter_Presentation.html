01

Foundations, fast

Three ideas we need before the architecture lands: how diffusion generates, what the UNet is, and what LoRA does.

  • "Three quick slides, then the interesting part." Experts can coast.

The problem

Text alone can't say where or how

"A car on a rainy street" gives you a car somewhere — but not this layout, this pose, or that look. Two kinds of control that don't fit in a prompt:

Structure conditioning

"Put the shapes here." Driven by a spatial map — depth, segmentation, edges. Controls where & what form.

← what our segmentation work drives

Style conditioning

"Make it look like this." Driven by a reference image's embedding. Controls global appearance & texture.

LoRAdapter's promise: both from one mechanism, added to a frozen model, few parameters. Our contribution: make segmentation a first-class structure signal in that mechanism.
  • Plant structure vs style — the spine of the talk; structure is our lane.
  • Prompt = semantics; structure = spatial arrangement; style = artistic look.

Crash course · the generator

How Stable Diffusion makes an image

Two facts we lean on: the whole backbone stays frozen (that's the efficiency), and convs decide shape while attention carries text — so structure conditioning targets the convs and leaves text alone. The map must reach all 4 depths — the mapper (Part 3) solves that.
  • Analogy: sculpting from noise; the UNet chips noise each step under the prompt's guidance.
  • Load-bearing facts: (1) backbone frozen → cheap; (2) convs = shape, attention = text → tells us where to inject. Don't over-explain internals.
  • "4 depths + must reach all of them" foreshadows the mapper.

The building block

LoRA in one slide

Instead of retraining a big frozen matrix W, learn a cheap low-rank correction beside it.

  • W frozen — all pretrained knowledge preserved.
  • A projects down to a tiny rank; B projects back up. Only A, B train.
  • B starts at zero → training begins as a perfect no-op.
  • A rank-128 pair is a rounding error next to a full matrix.
The catch: classic LoRA is static — once trained, B·A does the same thing to every input. The next idea removes exactly that limitation.
  • Analogy: W is a textbook you can't rewrite; A/B is a thin sticky-note correction on top.
  • End on the word static — the setup for the whole contribution.
02

The core idea: conditional LoRA

One block whose correction is computed live from an external signal — and the same block handles structure and style.

  • "The idea the paper is about — and why we could bolt segmentation on so cleanly."

The mechanism · FiLM

Let a signal reshape the LoRA branch

Insert a conditioning signal c that modulates the low-rank branch every forward pass — via FiLM: a learned scale γ and shift β derived from c.

γ = scale(c)
β = shift(c)
out = γ · A(x) + β

The correction is computed from c, live, every step — which is what makes control zero-shot: hand it a map it's never seen and it obeys.

  • The pivot. "Static LoRA memorises one correction; conditional LoRA takes a fresh instruction each time it runs."
  • FiLM is friendly: "just multiply-and-add, but the numbers come from your signal." γ starts ×1, β at 0 — no-op at init.

The block · src/lora.py — the whole architecture in one picture

The conditional-LoRA block

Read it: W(x) runs untouched · the map c never touches x, it only reshapes the tiny A→FiLM→B branch · the result is added on top, scaled by a live λ (lora_scale) you can dial 0 → off anytime.
  • THE centerpiece. Trace the two paths out loud: blue W is the untouched base; amber is x→A→FiLM(modulated by the seg map)→B→scaled by λ→added to W. The animated amber wires show the signal flowing.
  • Everything else in the talk is "where does this block live and how does c arrive." If they get this diagram, they get the paper.
  • λ is read live every forward pass — that's the inference knob in Part 5.

One block, two jobs · when to use what

Structure vs style — and how you tune it

Structure

Controls: spatial layout & form — where things go.

Signal c: a spatial map (depth / segmentation), per-pixel.

γ, β are: 1×1 convs → a different scale/shift at every pixel.

Use when: you have a mask / layout the image must follow.

Style

Controls: global appearance & texture — how it looks.

Signal c: a single pooled vector (CLIP embedding of a reference).

γ, β are: linear layers → one scale/shift for the whole feature.

Use when: you want to match a reference image's look.

Tuning — one knob, both modes: lora_scale is read live every step. 1.0 = full control · 0 = off · decay it across steps to lock layout early then hand appearance back to the model. For structure, a softening kernel blurs hard silhouette edges. Same equation throughout — only the shape of c changes. That unification is why the parameter count stays tiny.
  • The "aha" behind the title — CTRL (structure) or ALT (style), one formulation. Only real code difference: c is a spatial map (convs) or a pooled vector (linears).
  • Tuning payoff: lora_scale = master dial; decay trades rigidity for realism; kernel = structure-only edge softener. All inference-time.
  • Unification = not paying for two control systems, and our new seg source rides the same rails.

  • adaption_mode: only_res_conv wraps only conv1 of the first two ResNet blocks per stage.

The trick · zero framework changes

Inserted by a single setattr

  • For each matched layer: build a NewStructLoRAConv, copy the original pretrained weights into its frozen W, then swap it in:
setattr(parent, "conv1", lora)
  • Diffusers' own code still calls self.conv1(x) — and transparently runs the LoRA math. It has no idea anything swapped.
  • No hooks, no monkeypatch, no forked diffusers. PyTorch's dynamic attribute lookup does the rest — survives upgrades.
  • Genuinely elegant — dwell. Zero diffusers changes = works with stock pipeline, survives upgrades.
  • Analogy: didn't rewrite the recipe; swapped one ingredient jar for a smarter one that looks identical.
  • This is why our seg extension was clean — we never touched this machinery.

The whole picture · one denoising step

One map → the entire UNet

The efficiency: one mapper pass makes exactly 4 conditioning maps; each wrapped conv1 grabs cs[depth] — its own resolution. Down & up paths at one resolution share a map. One pass conditions the whole UNet, per step.
  • Money slide — pause. The mapper fans one map into 4; the depth index routes each to the right layer; mirror paths reuse maps.
  • Answers the "reach all 4 depths" question from Part 1.

Our contribution · the approach

Add a new modality without touching the core

  • Starting point: LoRAdapter ships depth (via MiDaS) and style. Segmentation is not in the paper — no stock seg encoder exists.
  • Goal: make segmentation a first-class structure signal, and compare depth- vs seg-conditioned generation head-to-head.
  • Principle: mirror the depth pipeline exactly. Build our seg encoder to satisfy the same encoder-slot contract → it drops into the same chain with zero changes to model.py or the mapper.
Discipline that kept it comparable: four strictly separated stages — depth-calc, depth-train, seg-calc, seg-train. Calculation never mixes with training; depth and seg never share code paths. That's what makes a depth-vs-seg comparison scientifically valid.
  • Core engineering flex: added a whole modality with zero model-core changes — by respecting the contract instead of hacking around it.
  • "Mirror depth exactly" is deliberate — the end goal is a fair depth-vs-seg comparison, valid only if pipelines are identical except the signal.

The key design decision

Colour, not raw class-IDs

Why it's the crux: the mapper is a conv built for depth's continuous gradient. Colourising turns categorical labels into a signal it can actually read — and a fixed palette guarantees train/inference parity (same class → same colour, always). We save raw IDs and colourise at load, so a palette change never re-runs the segmenter.
  • Shows we understood the architecture, not just wired it. The categorical-vs-continuous insight is why colourisation is non-negotiable.
  • NEAREST-only is subtle but critical — bilinear would fabricate class labels at boundaries.
  • Save-IDs-colourise-at-load: palette is a free, re-runnable choice, and it enforces parity.

Making it survive real data

Bugs we found & fixed on real maps

16-bit format

Real CARLA masks are I;16 PNGs, not 8-bit. We read raw pixels (no .convert("L")) — labels survive any Pillow version.

Parity rule

Train & inference maps must use the same model + preprocessing + value range, or distributions diverge.

resize_mode toggle

letterbox (keep whole scene + pad band) vs CenterCrop (crop edges) — the mask uses the same geometry as its RGB, so they can't drift apart.

The alignment bug — fixed 5db3624

Non-square 1280×800 masks were NEAREST-stretched to square while the RGB was letterboxed → up to 96px / ~19% misalignment at frame edges. Conditioning and target disagreed on where content sits. Fix: letterbox the mask with matching geometry.

These aren't a port — this is the unglamorous, load-bearing work of making a research pipeline hold up on real simulator data.
  • Frame as "what breaks leaving the paper's clean setup for real CARLA data." Each was a genuine bug with a real fix.
  • The alignment bug is the strongest story — a ~19% spatial mismatch between conditioning and supervision, invisible until you inspect real output. Cite the commit.
  • Parity rule = the single most important reproduction lesson. Say it slowly.

One contract, two front-ends

Two ways to make the map: SegFormer & Grounded-SAM

Both satisfy the same encoder-slot contract, so they're interchangeable — the generative core never changes. Only the front end differs:

The point isn't the table — it's the design. One contract absorbs a real-world segmenter and a simulator's native labels with no core change. SegFormer = general + self-scoring (mIoU) but 19 fixed classes; Grounded-SAM = 29-class richness + free sim labels, but no live inference.

  • mIoU asymmetry is the interesting one: SegFormer grades its own output; Grounded-SAM can't, so we skip rather than fake it.
  • Separate branches keep taxonomy/format assumptions from leaking between pipelines.

The seg pipeline's limitation · our diagnosis

"Fits the shape, but not the look"

γ and β are 1×1 convolutions — a one-pixel receptive field. Inside a flat, single-class region (a car's interior), every pixel gets the same scale/shift.

  • The signal there says only "this class is here" — zero appearance information.
  • Depth dodges this (varies continuously inside an object); a categorical seg map doesn't — a segmentation-specific limitation.
  • Full-strength conditioning runs through every denoising step — even the late ones that decide texture.

Two fixes — no retraining

lora_scale decay: hold conditioning strong early (lock layout), fade it late so SD's own prior fills in appearance.

conditioning kernel: soften hard silhouette edges before the mapper — smooths cut-out boundaries.

both operate purely on the mechanism from Part 3

The payoff of understanding the architecture: knowing where the block sits told us why segmentation looks generic in flat regions — and that both fixes are cheap, inference-time, retraining-free.
  • Our value-add insight, from reading code. Chain it: 1×1 conv → one-pixel receptive field → flat region carries no appearance → late steps starved → fix by decaying late + softening edges.
  • Stress it's seg-specific — depth doesn't suffer this. Answers "SegFormer or Grounded-SAM?" — it's about categorical segmentation, common to both.

The second artifact · the letterbox pad-band

Why the padding shows up in the output

We letterbox non-square frames to 512² by adding flat bands top & bottom (SquarePad). Intuition: "that's just padding — it should stay inert." It doesn't. Three reasons, in code:

  • Padding is real pixels, not a mask. The letterboxed 512² is the training target — get_input VAE-encodes the whole image, band included, into the latent the model learns to reconstruct.
  • The seg map's band is a real conditioning colour (Unlabeled). It FiLM-modulates the LoRA in that region — actively steering it, not ignoring it.
  • Every pair has the same band, same place → the model reliably learns "band here → flat pad colour" and dutifully renders it.

"Shouldn't it be static noise?"

No — we add a definite flat colour, not noise. And diffusion denoises the entire latent to a plausible image; there's no per-pixel "ignore" mask in the loss. The pad is supervised exactly like real content.

The real fix

Don't pad at all — train at native aspect ratio (e.g. 512×320), so there's no band to learn. (Or mask the loss in the pad region — not done here.)

Root cause in one line: letterbox padding is treated as real, supervised image content on both the seg-map input and the RGB target — so the model faithfully reproduces it. src/data/transforms.py · src/data/local_seg.py · src/model.py get_input
  • This directly answers "why does the padding get rendered — shouldn't it be inert noise?" The answer is code-grounded: the pad is real pixels on both the conditioning map and the target, and there's no loss-masking to tell the model to ignore it.
  • Key correction to the intuition: padding ≠ noise. We add a flat colour, and diffusion has no notion of "ignore this region" — it denoises the whole 512² to a plausible image.
  • The genuine fix is native aspect ratio (512×320) — no band exists to learn. That's a design change, not yet implemented.
